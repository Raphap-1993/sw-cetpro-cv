# 01.02 - Benchmark de referencias CETPRO y arquitectura web objetivo

## Identificacion
- id de cambio: `CHG-SWCV-001`
- fase actual: `Fase 1 - Analisis y requerimientos`
- estado: `aprobada por usuario`
- fecha: `2026-05-26`
- proyecto: `sw-cetpro-cv`

## Roster oficial aplicado
- `Raphael`: coordinacion de arquitectura y criterio de homologacion.
- `Patroclo`: analisis funcional, benchmark y aterrizaje del criterio institucional peruano.
- `Aether`: evaluacion de arquitectura publica, UX y jerarquia de contenidos.
- `Delta`: consolidacion documental y trazabilidad del artefacto.

## Objetivo
Definir un benchmark canonico balanceado de referencias `CETPRO/CEPRO`
peruanos para convertirlo en una arquitectura web objetivo ambiciosa para
`CETPRO Cesar Vallejo`, alineada a criterio institucional peruano, claridad de
informacion y captacion efectiva mediante preinscripcion simple por programa.

## Decisiones ya cerradas
- alcance de referencia: `5` sitios `CETPRO/CEPRO` peruanos.
- fuente de seleccion: fuentes oficiales o cuasi oficiales peruanas, filtradas
  luego por calidad publica del sitio.
- profundidad de recoleccion: todo lo publico relevante, sin zonas privadas ni
  paneles internos.
- entregable principal: benchmark + dataset resumido + arquitectura web
  objetivo + backlog priorizado.
- nivel de arquitectura objetivo: `maximo institucional`.
- cobertura territorial: `una sola sede actual`.
- criterio editorial inicial: `CRUD simple` con campos fijos por pagina.
- fuente de verdad para compliance: mezcla de criterio oficial peruano y
  benchmark de sitios reales.
- accion principal del sitio objetivo: `iniciar preinscripcion o admision`.
- profundidad del flujo publico inicial: preinscripcion simple por programa con
  registro en BD y correo.
- paquete obligatorio de paginas: institucional + admision + compliance +
  vida estudiantil + testimonios + galeria + base para crecer luego.
- criterio de evaluacion comparativa: equilibrio entre `compliance`,
  `arquitectura clara` y `conversion publica`.
- ambicion del rediseño objetivo: rehacer la arquitectura completa si hace
  falta, no solo corregir la estructura actual.

## Problema a resolver
El sitio actual de `CETPRO Cesar Vallejo` necesita una base objetiva para
reordenar su arquitectura publica, corregir huecos de UX y cerrar brechas de
informacion institucional, admision y compliance sin improvisar criterios pagina
por pagina.

El benchmark debe evitar dos errores:
- copiar de forma literal sitios de terceros;
- tomar decisiones de IA y contenidos solo desde intuicion local.

## Alcance del benchmark
Para cada referencia seleccionada se debe levantar:
- menu principal y secundario visibles.
- mapa de paginas publicas relevantes.
- cobertura institucional.
- cobertura de programas o especialidades.
- flujos publicos de contacto, solicitud de informacion, WhatsApp,
  preinscripcion o admision.
- documentos visibles y senales de compliance.
- patrones de CTA y conversion publica.
- observaciones de arquitectura, profundidad de navegacion y consistencia
  editorial.

## Fuera de alcance en esta etapa
- copiar textos, imagenes o activos de terceros.
- scraping masivo indiscriminado sin normalizacion.
- carga inmediata de datos a la BD del proyecto.
- implementacion visual o de frontend.
- cambios de runtime, deploy o dominio.
- ingreso a zonas privadas o paneles internos.

## Metodologia propuesta
1. Seleccionar la muestra desde fuentes oficiales o cuasi oficiales del ecosistema peruano.
2. Filtrar `5` referencias con web publica suficientemente util para benchmark.
3. Capturar la estructura publica de cada sitio con una ficha canonica comun.
4. Normalizar paginas, flujos, documentos y senales de compliance para
   comparacion transversal.
5. Puntuar cada sitio en tres ejes:
   - `compliance institucional`
   - `arquitectura y navegacion`
   - `conversion y admision`
6. Traducir los hallazgos a una arquitectura objetivo propia para
   `CETPRO Cesar Vallejo`.
7. Convertir esa arquitectura a backlog priorizado para siguientes fases.

## Estructura del dataset resumido
### 1. Sitios de referencia
- `site_id`
- nombre institucional
- tipo de entidad
- URL base
- fuente oficial de referencia
- notas de contexto
- score por ejes y score consolidado

### 2. Mapa de paginas
- `page_id`
- `site_id`
- titulo
- URL o slug
- tipo de pagina
- ubicacion en menu
- nivel jerarquico
- CTA principal
- observaciones de estructura

### 3. Senales de compliance y activos institucionales
- tipo de activo o pagina
- enlace visible
- disponibilidad publica
- observacion de cumplimiento o brecha

### 4. Flujos publicos
- `flow_type`
- pagina origen
- si es por programa o general
- cantidad aproximada de campos
- complejidad
- CTA
- canal de salida
- observaciones

### 5. Lectura UX/IA resumida
- claridad del menu
- consistencia institucional
- profundidad de navegacion
- fuerza de conversion
- patron rescatable
- problema visible

## Arquitectura web objetivo esperada para CETPRO Cesar Vallejo
La salida de este benchmark debe proponer una arquitectura objetivo:
- institucionalmente fuerte y apta para una sola sede actual.
- amplia, no minimalista, con cobertura suficiente para admision, compliance,
  vida estudiantil y confianza institucional.
- orientada a preinscripcion simple por programa como CTA dominante.
- gobernable desde un modelo editorial simple por CRUD, sin constructor libre.
- preparada para crecer despues a mas activos institucionales, testimonios,
  convenios, empleabilidad y secciones estrategicas.

## Contenido gestionable desde datos en primera version
Debe quedar identificado como gestionable por BD:
- programas y fichas de programa.
- banners y hero del home.
- noticias o novedades.
- paginas institucionales basicas.
- paginas de admision y preguntas frecuentes.
- formularios y definicion de destino por flujo.
- documentos y enlaces de compliance.
- testimonios, galeria y bloques institucionales basicos.
- sedes o datos de contacto de la unica sede actual.

## Entregables del subproyecto
1. Benchmark comparativo de `5` referencias `CETPRO/CEPRO`.
2. Dataset resumido y versionado en el repo.
3. Matriz comparativa por ejes de `compliance`, `arquitectura` y `conversion`.
4. Arquitectura web objetivo para `CETPRO Cesar Vallejo`.
5. Mapa de contenidos CRUD de primera version.
6. Backlog priorizado de cambios para bajar a `Fase 4`, `Fase 5` y `Fase 6`.
7. Lectura de brecha entre el sitio actual y el estado objetivo.

## Salida esperada hacia fases siguientes
- `Fase 1`: benchmark consolidado, requerimientos y brecha actual vs objetivo.
- `Fase 4`: specs por frente, al menos:
  - arquitectura y navegacion publica
  - programas y fichas con fotos reales
  - flujo de preinscripcion simple por programa
  - paginas de compliance e institucionales
  - modelo CRUD/backoffice de contenido publico
- `Fase 5`: implementacion por paquetes priorizados.
- `Fase 6`: QA funcional, visual y de conversion sobre la nueva arquitectura.

## Criterios de aprobacion de este subproyecto
- la muestra queda justificada y no es arbitraria.
- cada referencia se describe con una ficha comparable y trazable.
- la arquitectura objetivo deja claro que paginas entran, cuales son
  obligatorias y cual es la CTA principal.
- el modelo CRUD objetivo queda definido sin constructor libre ambiguo.
- el backlog resultante permite abrir specs de implementacion sin volver a
  discutir el benchmark desde cero.

## Riesgos y guardrails
- riesgo de sobrerrecolectar informacion sin traducirla a decisiones utiles.
- riesgo de benchmark visual sin sustento institucional peruano.
- riesgo de querer implementar frontend antes de cerrar la arquitectura
  objetivo y el backlog derivado.

Guardrails:
- normalizar antes de concluir.
- no copiar contenido literal.
- mantener la referencia a una sola sede actual.
- no abrir implementacion hasta cerrar el benchmark y su backlog.
